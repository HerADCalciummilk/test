# 权重融合

## 基本信息

- 算法名称：`00_blend`
- 源文件：`weight_blending.py`
- 算法类型：多预报融合
- 作者：wangyu / NMC
- 时间：2023-07-17

## 算法功能

把多家预报按评分合成一个场。评分越小表示越准，默认权重是评分的 `-2` 次方，所以评分小的预报占的比重更大。某一家预报或评分缺测时，在对应位置放 `None`，这一家不参与该次融合。

例如两家 2 米温度，评分分别是 `1` 和 `2`：

- 第一家权重 `1 ** -2 = 1`
- 第二家权重 `2 ** -2 = 0.25`
- 融合值 = `(预报1 × 1 + 预报2 × 0.25) / (1 + 0.25)`

格点评分会先换成权重，再用 `51×51` 的均值平滑，避免区域模式只在局部有值时权重出现硬边界。站点一维评分不做这步平滑。缺测格点不进入分子和分母，权重接近 `0` 的位置改成 `1` 再相除，避免除零。

## 主要入口

- `src/weight_blending.py`
  - `WeightBlending(wfunc=lambda x: np.power(x, -2), tolerate_period_mismatch=False)`
  - `WeightBlending.process(fcst_cubes, factor_cubes)`

`fcst_cubes` 和 `factor_cubes` 等长，元素是 `iris.cube.Cube`。`factor_cubes` 放 MAE、RMSE 这类评分。

`tolerate_period_mismatch` 会记在对象上。当前 `process` 没有读取它。

## CLI 示例

在本包目录下执行。没写的参数先读 `resource/blend.ini`，配置里也没有再用代码预设。这条命令只确认权重指数，不读取预报文件。

```bash
python -m cli.weight_blending_cli
```

```bash
python -m cli.weight_blending_cli --weight-power -2
```

```bash
python -m cli.weight_blending_cli --tolerate-period-mismatch
```

Python 调用：

```python
from src.weight_blending import WeightBlending

result = WeightBlending().process(fcst_cubes, factor_cubes)
```

## 依赖与运行条件

融合本身依赖 `iris`、`numpy`、`opencv-python`，以及 NIMM 里的 `PostProcessingPlugin`、`utils.cube_checker`、`nimm.metadata.utils`。命令行查看参数时不加载这些库。

原始示例使用的业务路径是 `z:/ECMWF/T2M/...` 和 `z:/GRAPES_GFS/T2M/...`，样例数据没有放进本目录。

## 当前限制

- 命令行不接收预报文件。Cube 由 `process` 传入。
- 平滑窗口固定为 `51×51`，没有做成命令行参数。
- `tolerate_period_mismatch` 目前只保存，不改变融合结果。
