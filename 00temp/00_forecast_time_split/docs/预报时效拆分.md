# 预报时效拆分

## 基本信息

- 算法名称：`00_forecast_time_split`
- 算法类型：预报场时间预处理
- 作者：cheny
- 时间：2024-04-15

## 解决的问题

数值预报经常是 3 小时一帧，下游却要 1 小时或 10 分钟一帧。这个模块把粗时效沿时间插值成细时效，也可以把多个时次的文件在时间维上拼成一块。

它不做订正，也不改空间网格。只处理时间维。

## 算法功能

- `TimeSplit`：按输入时效读一组格点，插值到更密的输出时效。可选把 U、V 合成风速，或按时效做差分。给出输出模板时，每个时效写成一个 nc，负值改成 `0`。
- `Timesplit_hourtomin`：把小时时效或起报时间轴线性插值到更细间隔。默认 10 分钟，并在前面补一个零场。
- `Readdata_fromtime`：按时间列表读取同一路径模板下的多个 nc，裁到指定经纬度范围，拼成 `member,time,dtime,level,lat,lon`。

## 主要入口

- `src/cal_griddata_TimeSplit_plugin.py`
  - `TimeSplit.process(input_fmt, time)`
- `src/timesplit_hourtomin_plugin.py`
  - `Timesplit_hourtomin.process(fcst, fcst0=None)`
- `src/readdata_fromtime_plugin.py`
  - `Readdata_fromtime.process(file_path, file_time, glon, glat)`

`TimeSplit` 还依赖包外的 `read_multi_griddata`、`cal_wswd_from_meteva_uvgrid`。`Readdata_fromtime` 依赖包外的 `dlonlat_info`。

## 目录说明

- `src/`：三个时效处理插件。
- `cli/`：每个源码主模块一个入口，文件名是模块名加 `_cli`。
- `resource/timesplit.ini`：命令行未显式传入的参数先读此文件，再没有则用预设。
- `utils/util_env.py`：读取 `resource/timesplit.ini`。
- `test/`：命令行缺省参数测试。
- `nbs/`：命令行调用示例 notebook。
- `docs/`：本说明。

## CLI 示例

在本包目录下执行。没写的参数先读 `resource/timesplit.ini`，配置里也没有再用代码预设。路径和时效列表两边都为空时会报错。这条命令确认参数，不读取预报文件。

```bash
python -m cli.cal_griddata_TimeSplit_plugin_cli --input-fh 0,72,3 --output-fh 0,72,1 --input-fmt <预报模板> --time 2023070100
```

```bash
python -m cli.timesplit_hourtomin_plugin_cli --ntime 10
```

```bash
python -m cli.readdata_fromtime_plugin_cli --file-path <路径模板> --file-time 2023070100,2023070101 --glon 70,140,0.05 --glat 0,60,0.05
```

`hourtomin` 预设间隔 `10`、单位分钟、沿 `dtime` 插值。`timesplit` 的插值方法预设 `slinear`。

## 依赖与运行条件

实际拆分依赖 `meteva_base`、`xarray`、`numpy`、`pandas` 和 NIMM 的 `PostProcessingPlugin`。命令行查看参数时不加载这些库。

## 当前限制

- 命令行只整理参数，格点读写仍在插件的 `process` 里。
- `TimeSplit` 构造函数里的 `np.arrage` 是源码拼写，`output_fmt`、`uv_fmt`、`delta_hour`、`is_fill0` 没有写进 `self`。
- `Readdata_fromtime.process` 的定义没有 `self`。
- 没有随包样例数据。
