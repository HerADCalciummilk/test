# NIMM 算法 ShowDoc 页

## 目的

从当前**模板页**抽出通用写法，供任意算法**生成或修改** ShowDoc 页（含日后新增算法）。  
内容从代码与 [算法清单](https://www.showdoc.com.cn/2598854776811541/11559060627551917) 归纳；版式以本 Skill + 模板为准。

| 插件模板 | `orographic_temperature_downscaling` page_id `11559060627552402` |
| CLI 参考（结构参考；有检验时表式对齐该页） | 同包 CLI 页 `11559060627556703` |

冲突时：**模板页版式 > 本 Skill > 旧算法页习惯**。种类与类别以**算法清单**为准。

**算法功能与流程**图：按模板画**框架**（输入 → **入口类名** → 输出；多入口时画支路/衔接）。图中必须出现入口名；禁止「提取经纬 / 积分 / 梯度→幂次」这类内部步骤图。写页前自检，不达标先改图。

## 默认必写（模板必选项）

为某算法生成 ShowDoc 时，**默认同时写插件页与 CLI 页**，且每页都包含：

| 页 | 必写 |
| --- | --- |
| **插件页** | **基础说明**（基础信息、流程、入口签名与参数表等）+ **使用示例** |
| **CLI 页** | **基础说明**（基础信息、怎么跑、CLI `process`/调度说明等）+ **使用示例** |

**CLI 批量调度**：

- 包内存在按目录列出文件、多时次循环、`runner` 批处理等用法时，CLI 页**应写批量调度示例**（可独立 `# 批量调度示例`，或并入使用示例，须带注释；能画结果场则贴图）。
- 仅有单次 `process`、无批量场景时**可省略**，在基础说明里一句说明「本包以单次调用为主」即可。
- 不要把温度降尺度模板里的路径/时次原样抄到无关算法。

用户明确说「只要插件页 / 只要 CLI / 只改示例」时可裁剪；未声明则按上表做全（含适用时的批量调度）。

**检验结果（默认不加；要写则按固定流程与表式）**：见下文「批量调度 → 检验 → 写页」。禁止抄模板数字。

修改已有页：只收敛偏差，保留已正确章节与附件。

## 预报种类与算法类别

- 基础信息里的 **预报类型** = 清单列 **预报种类**（如 `时空映射(降尺度)`）。
- **算法类别** = 清单列 **类别**（如 `00space_downscale`）。
- 按**包名**在清单中的行抄写，勿臆造。完整对照见 [categories.md](categories.md)。

## 插件页 vs CLI 页

| | 插件页 | CLI 页 |
| --- | --- | --- |
| 基础说明 | 算法含义、`process`、单位、流程 | 路径、子命令、调度入口 |
| 使用示例 | 调插件的可运行示例（**有本机可读真实样例则优先用**；否则自建） | 路径传入 `process` → print/图（图宜精简）；有批量则另写/兼写批量调度；数据策略同左 |
| 检验 | 不写长篇业务检验表 | 用户要检验且路径齐备时：先调度出方法结果再检验，表式对齐模板（订正前/后） |
| 不写什么 | — | 重复整份插件公式（链到插件页）；**不要**默认读 `resource/cli_input` 当示例源（`main` 默认可一句提及） |

## 使用示例要求

**插件页与 CLI 页**的「使用示例」均须有（缺一不可）：

1. **可运行代码**，关键步骤有**中文注释**（帮助理解，非复述参数表；宜注明数据来源与分辨率，如 EC 0.1°、1 km DEM）。
2. **代码输出**：`print(result)`（或等价）贴出**返回对象/场内容**，紧跟代码后用文本块。不要只打 `name`/`shape` 等元信息。CLI 与插件同级，不可只有调用代码。

**作图（鼓励、不强制全部算法）**：

- 输入/输出若是格点场、站点分布等**适合可视化**的数据，**应出图并贴图**，用于展示处理效果（对比前/后更佳）。
- **作图工具（必守）**：格点场统一用 `meteva_base.tool.plot_tools.pcolormesh_2d_grid` 出 PNG。**不要**在正式示例里用裸 `matplotlib.pyplot.pcolormesh` 另写一套（难统一色标与全库风格）。
- **预定义要素图例（必守，有则用）**：`pcolormesh_2d_grid` **不会**按要素自动选色标（默认 `cmap="rainbow"`）。若 `meteva_base.tool.color_tools` 对该要素有定义，**必须用库内预置图例**，不要靠自动色标或随意 `rainbow`。常用名：`rain_1h` / `rain_3h` / `rain_24h`（及对应 `*_error`）、`temp_2m`、`rh`、`wind_speed`、`vis`、`tcdc` 等（见 `color_tools.cmaps` / `get_cmap_and_clevs_by_element_name`）。调用时传 `cmap="rain_1h"`（或先取 `cmap,clevs` 再传入）。无预置时再自定 `clevs`/`cmap`。
- **统一图例（必守）**：同一要素、且为算法处理前/后（或输入/输出/实况对照）的多张图，必须共用同一套色标/`clevs`（及同一 `cmap`）。有预置图例时，对照图一律用同一预置名（如订正前/后/实况降水都用 `rain_1h`），便于观测对比。典型如「订正前气温」与「订正后气温」。
- **差值/增量图（默认不画；仅下列情况可画）**：
  - **可画**：同要素「输入场 − 处理结果」（或处理前 − 处理后），突出算法改动量（对齐模板订正页）；或业务上明确的两种**方案/产品**对比（非「传不传可选参数」）。
  - **禁止画**：「有可选输入 / 非默认参数」相对「默认缺省」的差值（如含海拔与浑浊度 − 默认海拔 0、浑浊度 3）。此类只证明传参会变，无业务信息量——**只给绝对场**（有输入与默认若都要展示，两张绝对场即可）。
  - **禁止画**：输入与输出物理量不同、不可减（如晴空：气象输入 vs 辐照输出）。
  - 画了则单独色标：优先用预置误差图例（如 `rain_1h_error`、`wind_speed_error`）；否则用中心为 0 的方案（如 `me`/`bwr`）。引导句或图注写清「差值 = A − B」。差值图**不能替代**订正前/后（及有检验时的实况）绝对场。
- 不同要素（气温 vs 地形 vs Γ）各自独立色标，不要求互相同一。
- **图题**：不要写「合成」；「合成 / 仅演示」放在引导句或代码注释。图题用 ASCII `-`，不用 Unicode 减号。
- 若数据本质不便画图（纯标量配置、抽象表、无空间场等），可以只有代码 + 文本输出，并在引导句说明未作图原因（可选一句）。
- 能画却省略图 = 不符合本 Skill；不能画硬凑无意义的图 = 也不要求。

说明文字写在**正确的入口节**（勿串节）。

**同一入口仅一个「使用示例」标题（必守）**：示例走**一条主路径**；参数表已写清的可选功能（如有/无掩码）不必在示例里再各演示一遍。不同 `# 入口` 才各开一节。

### 示例数据：真实优先，自建兜底（必守）

示例目的是**让读者看出算法做了什么**。数据来源按优先级：

1. **用户提供本机可读真实样例路径**（从业务机/跳板拷到 Cursor 本机或已挂载）：**优先使用**。可选裁剪到效果可辨的子域（如强降水区）。引导句写清来源与分辨率；**不要**在发版正文写跳板 SSH/本机盘符联调话术。
2. **包内已备的裁剪真场**（如模板的 `resource/showdoc_demo`）：可用于与模板对齐的示例；ShowDoc 正文用**相对包路径**，勿写 `d:\...`。
3. **无真实路径时自建/合成**：须满足下方效果约束；引导句或注释写明「合成，仅演示」。**图题不要写「合成」**。

不论来源，均须：

1. **效果可辨**：处理后相对处理前肉眼可辨（订正增量、匹配前后等）。Δ≈0 则换数据或子域，勿交差。
2. **对准该方法**：触发本入口核心逻辑（足够 Δz、可匹配的分布差等）。
3. **避免假效果 / 脏图**：勿用毛刺/棋盘冒充细节；缺测勿拖垮色标；对比图共用色标。
4. **可移植导入（必守）**：示例代码**禁止** `sys.path.insert` 绑本机绝对盘符。假定包已可 `import`；正文**不要**写「把 `00temp` 加入 `PYTHONPATH`」。Agent **本地跑图/算检验**可用用户给的绝对路径；写入 ShowDoc 时改为相对包路径或中性示意路径。
5. **CLI 流程**：场就绪（真实读入或自建写盘）→ 路径传入 `process` → `print` / 画图。不要把示例写成直接读 `resource/cli_input` 当唯一数据源（`main` 默认可在基础说明一句带过）。
6. **禁止**：照搬模板页的地形/Γ/气温数字与 RMSE 表到其他算法。

仍允许生成后**少量打磨**；首版看不出效果视为未达标。

**远程机器**：本 Skill **不**经跳板 SSH 连业务机取数。用户负责把模式/实况/方法输入备到 **Cursor 本机可读**路径后再把路径交给 Agent。

## 批量调度 → 检验 → 写页

用户要「检验结果」或明确给齐业务数据做检验时，按下列顺序（**先调度，再检验**）：

1. **用户提供**（本机可读）：模式数据、方法输入（地形/掩码/辅料等）、实况；输出目录；时次窗口与时区对齐规则（如 EC 世界时、实况 BJT+8）。
2. **Agent 批量调度**：按该包 CLI/批处理跑通，写出**方法结果**（订正场/产品场等）。不要假设订正场已现成（除非用户声明已有结果、仅重算检验）。
3. **Agent 检验**：用方法结果（及订正前可比场，见下）对实况算 bias / RMSE。
4. **写入 CLI 页**：更新「数据图展示」（若有）与「**检验结果**」；数字必须来自本次计算，**禁止抄模板**。

### 检验表版式（对齐模板 CLI 页，必守）

有检验就写**订正前 / 订正后**对照（订正类算法用此称谓；其他算法可用「处理前 / 处理后」，列结构不变）：

- **订正前**：方法处理前、已与结果同网格的场 vs 实况（如 EC 插到目标网格后再比）。
- **订正后**：方法输出 vs 实况。
- **Δrmse** = 订正后 RMSE − 订正前 RMSE（负值表示改善）。

汇总表示例：

| 项目 | 订正前 | 订正后 |
| --- | ---: | ---: |
| mean_bias | **… K** | **… K** |
| mean_rmse | **… K** | **… K** |
| Δrmse | — | **… K** |

逐日（或逐时次）表须同时列出订正前/后的 bias、rmse 与 Δrmse。  
**禁止**只留订正后一列。缺路径或算不出则说明缺什么，**不编造**数字。

默认写页**不加**检验；用户未要检验且未给齐路径时不要强行加 RMSE 表。

## 工作流

```
进度：
- [ ] 1. 确认：新建/修改；是否裁剪；是否要检验（要则收齐本机路径）
- [ ] 2. 算法清单核对包名 → 预报种类、类别
- [ ] 3. 读代码：入口、默认值、单位、返回；有无 CLI
- [ ] 4. 打开 templates/plugin_page.md 与 templates/cli_page.md + style.md
- [ ] 5. 已有页则 get_page，保留正确部分；缺骨架字段时按模板补
- [ ] 6. 套用插件模板填 `{{…}}` + 按本 Skill 写示例 → ShowDoc
- [ ] 7. 套用 CLI 模板（有批量则含批量调度；无 CLI 则插件页注明并跳过）→ ShowDoc
- [ ] 8. 示例：真实路径优先 / 否则自建 → 注释 → 跑通 → 输出块 → 能画则出图上传
- [ ] 9. 若要检验：本机调度出方法结果 → 算订正前/后 RMSE → 写 CLI「检验结果」
- [ ] 10. 自检后请用户刷新
```

写入：小改 `update_page_diff`；大改 `update_page`。Token 不进 Skill。

**附件**：误传或占位图**不要反复调用** `delete_attachment`（普通权限常失败且易卡住）。正确做法：上传真图 → 更新正文 URL；未引用旧附件请用户在 ShowDoc 网页手动删（勿开「允许删除项目」）。

## 自检

- [ ] 预报类型、算法类别与清单一致
- [ ] 插件页与 CLI 页（若有）均有基础说明 + 使用示例；同一入口未重复 `**使用示例**`；未为参数表已覆盖的可选变体堆砌示例
- [ ] 有批量场景时 CLI 已写批量调度；无则未硬凑
- [ ] 插件与 CLI 示例均有注释 + 输出块；适合画图的已用 `pcolormesh_2d_grid` 贴图
- [ ] 有本机真实样例则已优先使用；否则自建且效果可辨；引导句可写「仅演示」，图题无「合成」
- [ ] 发版正文无本机绝对路径 / `sys.path` 绑死盘符；未要求用户把 `00temp` 加入 `PYTHONPATH`
- [ ] CLI 示例为「场就绪 → `process(路径)`」，未默认依赖 `resource/cli_input`
- [ ] 同要素处理前/后（及实况若有）对比图已统一色标；有预置要素图例（如 `rain_1h`）则已使用，未默认 `rainbow`/各图自动色标；无「有输入−默认」类差值图；若有差值则属输入−结果或方案对比、用误差/对称色标，且公式已写清
- [ ] 无检验需求时未强行加 RMSE；有检验则先调度再检验，表含订正前/后与 Δrmse，未抄模板数字
- [ ] 「算法功能与流程」Mermaid 含入口类名且为框架图，非内部流程图

- [ ] CLI 示例图未整套复刻插件页（通常 1–2 张结果场即可）
- [ ] CLI「怎么跑」表未把 `process` 当入口行；中文图题示例已设 YaHei/SimHei 等字体
