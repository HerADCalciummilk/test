# NIMM 算法 ShowDoc 页

## 目的

从当前**模板页**抽出通用写法，供任意算法**生成或修改** ShowDoc 页（含日后新增算法）。  
内容从代码与 [算法清单](https://www.showdoc.com.cn/2598854776811541/11559060627551917) 归纳；版式以本 Skill + 模板为准。

## 默认必写（模板必选项）

为某算法生成 ShowDoc 时，**默认同时写插件页与 CLI 页**，且每页都包含：

| 页 | 必写 |
| --- | --- |
| **插件页** | **基础说明**（基础信息、流程、入口签名与参数表等）+ **使用示例** |
| **CLI 页** | **基础说明**（基础信息、参数优先级、怎么跑、`XxxCli.call` 签名与参数表等）+ **使用示例** |

**CLI 与仓库约定（`CliBase`）**：

- **对外签名统一为 `XxxCli.call`**（关键字与命令行 flag 同名）；`return` 为退出码。需要场对象时读 `output_path`（或业务输出路径）。
- 模块内 `process` 可被 `run` 调用，**不是** CLI 页主签名；插件页仍写插件类 / `.process`。
- **参数优先级**：显式传入（命令行 flag / `XxxCli.call`）**>** 配置文件参数（ini 非空项）**>** 代码预设。空 ini 不覆盖上层。
- 「怎么跑」用法：无 `[]` = 必填，`[]` 内 = 可选。命令行示例集中在「怎么跑」，**使用示例不要再重复贴同套 bash**。

**CLI 批量调度**：

- 包内存在按目录列出文件、多时次循环、`runner` 批处理等用法时，CLI 页**应写批量调度示例**（可独立 `# 批量调度示例`，或并入使用示例，须带注释；能画结果场则贴图；优先 `XxxCli.call`）。
- 仅有单次调度、无批量场景时**可省略**，在基础说明里一句说明「本包以单次调用为主」即可。
- 不要把温度降尺度模板里的路径/时次原样抄到无关算法。

用户明确说「只要插件页 / 只要 CLI / 只改示例」时可裁剪；未声明则按上表做全（含适用时的批量调度）。

**检验结果（默认不加；要写则按固定流程与表式）**：见下文「批量调度 → 检验 → 写页」。禁止抄模板数字。

修改已有页：只收敛偏差，保留已正确章节与附件。

## 插件页 vs CLI 页

| | 插件页 | CLI 页 |
| --- | --- | --- |
| 基础说明 | 算法含义、插件构造/`.process`、单位、流程 | 怎么跑、`XxxCli.call`、参数优先级、配置 ini |
| 使用示例 | 调插件的可运行示例（**有本机可读真实样例则优先用**；否则自建） | `XxxCli.call` 写盘 → 读场 → print/图；**同要素可对照时须贴订正前+订正后**（勿只贴输出）；有批量则另写/兼写批量调度；数据策略同左 |
| 检验 | 默认不加。CLI 已有检验时：插件页可贴**一份汇总表**（mean_bias / mean_rmse / Δrmse），并链到 CLI；**不**贴逐日明细 | 用户要检验且路径齐备时：先调度出方法结果再检验；写完整表（汇总+逐日），表式对齐模板（订正前/后） |
| 不写什么 | — | 重复整份插件公式（链到插件页）；**不要**默认读 `resource/cli_input` 当示例源；不要在使用示例里重复「怎么跑」的整段 CLI |

## 使用示例要求

**插件页与 CLI 页**的「使用示例」均须有（缺一不可）。版式以模板页 `orographic_temperature_downscaling` 为准；近期约定侧重：**调用与作图拆开写**、对照图用 `creat_axs` 做底图。

**示例块固定顺序（必守，能画时）**：

1. **引导句**（数据来源、分辨率、本节演示什么）
2. **调用代码**（` ```python `）：只含读数 / 构造 / `.process` 或 `XxxCli.call` / `print`；**关键步骤有中文注释**（对新手友好：说明「这一步在干什么、数据从哪来」；**非**复述参数表；**少写**内部下标、BoundaryNorm 等实现细节）
3. **方法数据结果展示**：紧跟调用代码，用**无语言标记**的代码围栏贴 `print` 出来的返回对象/场内容（勿标 `text`；勿只打 `name`/`shape`）
4. **画图代码**（第二个 ` ```python `）：与调用代码**分开**，勿混在同一块；含字体、`cmap`/`clevs`、出图与 `savefig`
5. **贴图**：`![图题](url)`（引导短句可有）

禁止「只有贴图、示例里完全无画图代码」；也禁止把算法调用与大段作图揉成一块。不能画时：引导句 → 调用代码 → 结果块即可，并一句说明未作图原因。

**作图（鼓励、不强制全部算法）**：

- 输入/输出若是格点场、站点分布等**适合可视化**的数据，**应出图并贴图**，用于展示处理效果。
- **订正/降尺度等同要素对照（插件页与 CLI 页均必守）**：输入与输出为**同一物理量**时，使用示例须贴**订正前（输入）+ 订正后（输出）**两张绝对场，且共用同一套色标/`clevs`。**禁止只贴输出/结果场**（读者看不出算法改了什么）。差值图仍按下文「默认不画」；插件页可另加差值，CLI **默认不加**差值与辅料/多入口图。
- **不可对照时**：输入输出物理量不同（如气象入 → 辐照出）或无「处理前」可比场，贴输出绝对场即可，引导句可一句说明未贴输入原因。
- **作图工具（必守）**：
  - **单场**：格点用 `meteva_base.tool.plot_tools.pcolormesh_2d_grid`；站点用 `scatter_sta`。
  - **对照 / 多子图**：先 `meteva_base.creat_axs(n, map_extend, ncol=..., add_index=True)` 建底图，再对各轴直接 `add_contourf(..., cut_colorbar=False)` + `ax.set_title(...)`（**不要**再包一层 `_compare`/`_panels` 辅助函数）。不用 `add_mesh` 做对照：它无 `cut_colorbar`，内部仍按各场 `vmin/vmax` 默认裁剪，易导致子图分级不一致。同要素对照共用 `cmap`/`clevs`。布局按内容定（常见 **1×2** 前后对照、**1×3** 多方案/多时次等），勿写死唯一规格。子图间距用 `wspace`（及必要时 `width`）按观感调整，**不要写死固定数值**；`creat_axs` 无 `hspace`，多行过紧则加大 `height`。中文图题与模板一致：只设 `plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "DejaVu Sans"]`、`axes.unicode_minus=False`（`pcolormesh_2d_grid` / `creat_axs`+`set_title` 同样适用；不必再上 `FontProperties`）。
  - **不要**在正式示例里用裸 `matplotlib.pyplot.pcolormesh` / `contourf` 另写一套（难统一色标与全库风格）。
- **预定义要素图例（必守，有则用）**：作图接口**不会**按要素自动选稳妥业务色标（默认常为 `rainbow`）。若 `meteva_base.tool.color_tools` 对该要素有定义，**必须用库内预置图例**。常用名：`rain_1h` / `rain_3h` / `rain_24h`（及对应 `*_error`）、`temp` / `temp_2m`、`rh`、`wind_speed`、`vis`、`tcdc` 等。
- **推荐写法（对照图必守）**：先取出预置对象再显式传入；画图代码里须能看到预置名或该调用：
  ```python
  import meteva_base as meb
  from meteva_base.tool.color_tools import get_cmap_and_clevs_by_element_name

  cmap, clevs = get_cmap_and_clevs_by_element_name("temp_2m")
  # 对照：creat_axs 底图 + add_contourf(cut_colorbar=False)
  axs = meb.creat_axs(
      2, map_extend, ncol=2, title_list=["处理前", "处理后"],
      add_worldmap=False, add_index=True, wspace=...,
  )
  meb.add_contourf(axs[0], grd_before, cmap=cmap, clevs=clevs, cut_colorbar=False, add_colorbar=True)
  meb.add_contourf(axs[1], grd_after, cmap=cmap, clevs=clevs, cut_colorbar=False, add_colorbar=True)
  ```
  单场格点：`pcolormesh_2d_grid(grd, save_path=..., title=..., cmap=cmap, clevs=clevs, show=False)`；单场站点：`scatter_sta(...)`。  
  对照须传入**同一** `cmap`/`clevs`，并对 `add_contourf` 设 `cut_colorbar=False`。无预置时再自定 `clevs`/`cmap`。
- **统一图例（必守）**：同一要素、且为算法处理前/后（或输入/输出/实况对照）的多张图，必须共用同一套色标/`clevs`（及同一 `cmap` 对象或同一预置名+同一 `clevs`）。禁止各图自动色标。
- **改图必重出（必守）**：更新「使用示例 / 批量调度 / 数据图展示」中的图时，必须**重新跑图画 PNG → `upload_attachment` → 正文换新 URL**。禁止只改文案/章节名却沿用旧附件。
- **差值/增量图（默认不画；仅下列情况可画）**：
  - **可画**：同要素「输入场 − 处理结果」（或处理前 − 处理后），突出算法改动量；或业务上明确的两种**方案/产品**对比（非「传不传可选参数」）。
  - **禁止画**：「有可选输入 / 非默认参数」相对「默认缺省」的差值；输入与输出物理量不同、不可减。
  - 画了则单独色标：优先预置误差图例；否则 `bwr`/对称色标、0 居中；正文写清「差值 = A − B」。差值**不能替代**绝对场对照。
- 不同要素各自独立色标，不要求互相同一。
- **图题**：不要写「合成」；「仅演示」放引导句或注释。图题用 ASCII `-`。
- 能画却省略图 = 不符合本 Skill；不能画硬凑无意义的图 = 也不要求。

说明文字写在**正确的入口节**（勿串节）。

**同一入口仅一个「使用示例」标题（必守）**：示例走**一条主路径**；参数表已写清的可选功能（如有/无掩码）不必在示例里再各演示一遍。不同 `# 入口` 才各开一节。

### 示例数据：真实优先，自建兜底（必守）

示例目的是**让读者看出算法做了什么**。数据来源按优先级：

1. **用户提供本机可读真实样例路径**（从业务机/跳板拷到 Cursor 本机或已挂载）：**优先使用**。可选裁剪到效果可辨的子域（如强降水区）。引导句写清来源与分辨率；**不要**在发版正文写跳板 SSH/本机盘符联调话术。
2. **包内已备的裁剪真场**（如模板的 `resource/showdoc_demo`）：可用于与模板对齐的示例；ShowDoc 正文用**相对包路径**，勿写 `d:\...`。
3. **无真实路径时自建/合成**：须满足下方效果约束；引导句或注释写明「合成，仅演示」。**图题不要写「合成」**。

不论来源，均须：

1. **效果可辨**：处理后相对处理前肉眼可辨（订正增量、匹配前后等）。Δ≈0 则换数据或子域，勿交差。
2. **对准该方法**：触发本入口核心逻辑（足够 Δz、可匹配的分布差等）。
3. **避免假效果 / 脏图**：勿用毛刺/棋盘冒充细节；缺测勿拖垮色标；对比图共用色标。
4. **可移植导入（必守）**：示例代码**禁止** `sys.path.insert` 绑本机绝对盘符。假定包已可 `import`；正文**不要**写「把 `00temp` 加入 `PYTHONPATH`」。Agent **本地跑图/算检验**可用用户给的绝对路径；写入 ShowDoc 时改为相对包路径或中性示意路径。
5. **CLI 流程**：场就绪（真实读入或自建写盘）→ `XxxCli.call(..., output_path=...)` → 读 nc → `print`；**作图另块**。不要默认把 `resource/cli_input` 当唯一数据源；引导句写清数据来源（如「样例来自 EC 模式场」），避免读者难懂的内部话术（如「与注释一致」「同域裁剪真场」堆砌）。
6. **禁止**：照搬模板页的地形/Γ/气温数字与 RMSE 表到其他算法。

仍允许生成后**少量打磨**；首版看不出效果视为未达标。

**远程机器**：本 Skill **不**经跳板 SSH 连业务机取数。用户负责把模式/实况/方法输入备到 **Cursor 本机可读**路径后再把路径交给 Agent。

## 批量调度 → 检验 → 写页

用户要「检验结果」或明确给齐业务数据做检验时，按下列顺序（**先调度，再检验**）：

1. **用户提供**（本机可读）：模式数据、方法输入（地形/掩码/辅料等）、实况；输出目录；时次窗口与时区对齐规则（如 EC 世界时、实况 BJT+8）。
2. **Agent 批量调度**：按该包 CLI/批处理跑通，写出**方法结果**（订正场/产品场等）。不要假设订正场已现成（除非用户声明已有结果、仅重算检验）。
3. **Agent 检验**：用方法结果（及订正前可比场，见下）对实况算 bias / RMSE。
4. **写入 CLI 页**：更新「数据图展示」（若有）与「**检验结果**」（汇总 + 逐日）；数字必须来自本次计算，**禁止抄模板**。
5. **同步插件页（若本包有检验）**：在插件页末、CLI 回链前贴**同一份汇总表**（只要 mean_bias / mean_rmse / Δrmse），一句说明窗口与订正前/后含义，并链到 CLI 看逐日明细；**不要**把逐日表再贴到插件页。

### 检验表版式（对齐模板 CLI 页，必守）

有检验就写**订正前 / 订正后**对照（订正类算法用此称谓；其他算法可用「处理前 / 处理后」，列结构不变）：

- **订正前**：方法处理前、已与结果同网格的场 vs 实况（如 EC 插到目标网格后再比）。
- **订正后**：方法输出 vs 实况。
- **Δrmse** = 订正后 RMSE − 订正前 RMSE（负值表示改善）。

汇总表示例：

| 项目 | 订正前 | 订正后 |
| --- | ---: | ---: |
| mean_bias | **… K** | **… K** |
| mean_rmse | **… K** | **… K** |
| Δrmse | — | **… K** |

逐日（或逐时次）表须同时列出订正前/后的 bias、rmse 与 Δrmse。  
**禁止**只留订正后一列。缺路径或算不出则说明缺什么，**不编造**数字。

默认写页**不加**检验；用户未要检验且未给齐路径时不要强行加 RMSE 表。

## 工作流

```
进度：
- [ ] 1. 确认：新建/修改；是否裁剪；是否要检验（要则收齐本机路径）
- [ ] 2. 算法清单核对包名 → 预报种类、类别
- [ ] 3. 读代码：插件入口 + CLI `XxxCli`/`flag`/`conf.ini`、默认值、单位、返回；有无 CLI
- [ ] 4. 打开 templates/plugin_page.md 与 templates/cli_page.md + style.md
- [ ] 5. 已有页则 get_page，保留正确部分；缺骨架字段时按模板补
- [ ] 6. 套用插件模板填 `{{…}}` + 按本 Skill 写示例 → ShowDoc
- [ ] 7. 套用 CLI 模板（有批量则含批量调度；无 CLI 则插件页注明并跳过）→ ShowDoc
- [ ] 8. 示例：真实路径优先 / 否则自建 → 调用代码 → 方法数据结果展示 →（能画则）画图代码 → 贴图上传
- [ ] 9. 若要检验：本机调度出方法结果 → 算订正前/后 RMSE → 写 CLI「检验结果」（汇总+逐日）→ 插件页贴同一份汇总表并链 CLI
- [ ] 10. 自检后请用户刷新
```

写入：小改 `update_page_diff`；大改 `update_page`。Token 不进 Skill。

**附件**：误传或占位图**不要反复调用** `delete_attachment`（普通权限常失败且易卡住）。正确做法：上传真图 → 更新正文 URL；未引用旧附件请用户在 ShowDoc 网页手动删（勿开「允许删除项目」）。
